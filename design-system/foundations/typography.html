Typefaces

Primary display: Montserrat (bundled OTF, 400–800) — titles, headings, eyebrows, kickers, on-bar labels. Body: Open Sans (bundled TTF) — panels, menus, inputs, captions. Monospace only for token values, never UI. Emphasis pattern: mix Light + Bold inside one headline to stress keywords.
Form controls do not inherit the document font — a bare <button> falls back to the browser's own UI font. App.css defaults every control to the body face in one base rule; never rely on inheritance to put a control in the brand.

Kickers and eyebrows carry the brand's wide tracking (.12em); everything else stays dense. Sentence case in titles — never Title Case.
A size does not settle the face. 11px is body-face secondary text and nothing else — the timeline month heading sat there at Montserrat 700, one pixel above the week labels beneath it, which is too small a gap to read as a hierarchy. It now takes the 12px step. Likewise 10px is the eyebrow: a section header is not entitled to 11px because it feels more senior, it earns that through its band, tint and accent edge.
Tracking is always em, never px. px tracking stops scaling with the size, so the same device drifts every time it is reused a step up or down — which is how the eyebrow ended up carrying .12em, 0.3px, 0.4px and 1px in different corners of the app.

The kicker device

Projects
The red kicker rule (28px × 3px) above an uppercase Montserrat label is the brand signature — used for panel headers, launcher sections, and empty-state headings. A thin red vertical bar to the left of a label is the sub-kicker for inline section labels.
